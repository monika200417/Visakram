# 01. EXPERIENCE NORTH STAR

## Core statement

> **Twenty years of construction experience, expressed through a contemporary digital experience.**

The website must communicate trust and capability first, while using motion, video and 3D to make the brand memorable.

The technology should remain invisible.

The visitor should remember:

- the quality of the work
- the people behind the company
- the projects
- the transparency of the process
- the feeling of a premium, established builder

Not the names of the animation libraries.

## Experience principle

**Motion carries meaning.**

A scroll-driven sequence is approved when it:

- explains a process
- reveals a transformation
- creates continuity
- focuses attention
- improves understanding
- makes the brand memorable

It should not exist simply because an effect is technically possible.

Current interaction guidance similarly emphasizes starting from the visitor goal and using motion as feedback rather than spectacle. citeturn0search8

# CHAPTER 07B — HOME TOUR

Placed between From Plan to Place and How We Build.

```text
From Plan to Place  → how the building comes to life
Home Tour           → what the finished space feels like
How We Build        → how Visakram manages the process
```

## Concept

"Experience spaces beyond walls." One villa, shown as photorealistic footage
scrubbed by the user's scroll. The camera's **time** moves along the chapters:

```text
01 Exterior → 02 Entry → 03 Living → 04 Dining → 05 Kitchen →
06 Staircase → 07 Bedroom → 08 Balcony → 09 Final Reveal
```

Footage is added chapter by chapter (the first two are Exterior and Staircase).
Real video on desktop (motion allowed); everything else gets a static block of
stills with the chapters as text.

**Current film (supplied Oct 2026):** a single 25.9 s, 1920×1080 walkthrough that starts inside the living room (there is no exterior shot). The shipped chapters are read off that footage and live in `src/data/homeTourFilm.ts`: 01 Living → 02 Kitchen → 03 Staircase → 04 Hallway → 05 Bedroom → 06 Balcony → 07 Ocean View → 08 Brick by Brick We Build Trust — "From First Sketch to Final Nail." (the last frame, the Visakram mark over the sea; client-supplied copy, formerly "Final Reveal"; "Brick by Brick" in orange, "We Build Trust" in white). On phones the picture is drawn back over the last seconds (homeTourFilmFit) so the whole logo fits the screen. The list above is the original plan; the footage is the source of truth.

## Rules

- No free camera, mouse-look, head bob, game movement or cuts.
- The residence is illustrative — not a Visakram project, no signage, no
  brand mark — and is labelled as such wherever it appears.
- Captions are the approved short lines only; no capability claims.
- Visually and emotionally distinct from From Plan to Place: warm, low,
  first-person, real footage, interior-led (vs. a cool, elevated construction study).

The dusk procedural version is archived in `docs/milestones/`.

Implementation: `src/media/home-tour/` (manifest, timeline, seeker) and
`src/sections/home/HomeTourSection/` (pin, media, overlay, journey line, fallback).

# 07. MOTION DESIGN SYSTEM

## Motion levels

### Level 0 — No animation

Critical content, forms, accessibility fallback.

### Level 1 — Micro

- hover
- opacity
- 1–2% scale
- arrow movement

### Level 2 — Editorial

- text reveal
- image clip
- section entrance
- subtle parallax

### Level 3 — Cinematic

- pinned sections
- scrubbed timelines
- image expansion
- horizontal story

### Level 4 — Signature

- 3D construction sequence

Level 4 should be rare.

---

# 08. MOTION TIMING

Initial design tokens.

These are starting points, not final values.

### Micro

150–300ms

### UI

300–600ms

### Editorial

600–1000ms

### Cinematic

1000–2000ms equivalent timeline

### Easing

Prefer:

- smooth ease-out
- custom cubic-bezier
- carefully controlled linear progress for scrubbed sequences

Avoid:

- excessive spring/bounce
- elastic effects
- random easing changes

---

# 09. SCROLL ARCHITECTURE

The site should retain native scrolling.

Scroll-driven sections should behave as chapters.

Recommended patterns:

### Reveal

Simple content reveal.

### Sticky narrative

Visual stays while text changes.

### Scrub

Scroll controls exact animation progress.

### Pin

Section temporarily owns the viewport.

### Horizontal

Use only for a specific project/story sequence.

### Avoid

- permanent scroll hijacking
- excessive pinned sections
- long horizontal journeys
- motion on every pixel of scroll

Current guidance for scrollytelling favors clear chapters, purposeful motion, reduced-motion fallbacks, and performance testing. citeturn0search5

- 3D timeline control

## Three.js / React Three Fiber

Use only for genuine 3D.

## Lenis

Use only if testing confirms that smooth scrolling improves the experience without compromising accessibility or input behavior.

# 11. PERFORMANCE ARCHITECTURE

Performance is part of design.

The site must not become:

> beautiful but slow.

### Critical path

Hero:

- optimized poster
- optimized video
- critical fonts
- minimal JS
- no 3D

### Below the fold

Lazy-load:

- project images
- testimonial video
- 3D assets
- non-critical modules

### Heavy modules

3D and complex animations must be code-split.

### Animation

Prefer compositor-friendly properties:

- transform
- opacity

Avoid repeated layout-triggering animation.

### Scroll

Never implement continuous scroll using React state updates for every frame.

Use:

- Motion values
- GSAP ticker
- browser-native scroll-linked APIs where appropriate

A current 2026 performance case study specifically recommends treating animation as a budget from the start rather than optimizing only after the design is complete. citeturn0search1

# 15. ACCESSIBILITY / REDUCED MOTION

Respect:

`prefers-reduced-motion: reduce`

Reduced version should:

- remove large parallax
- remove aggressive transforms
- replace scrubbed motion with stable states
- preserve all content
- keep navigation functional

A reduced-motion mode is a complete alternate experience, not a broken version.

# 25. DEFINITION OF PREMIUM

The website is not considered premium because it contains:

- Three.js
- GSAP
- a custom cursor
- smooth scrolling
- lots of transitions

It is premium when:

- the first impression is immediate
- typography feels intentional
- imagery is exceptional
- every transition has purpose
- scroll feels controlled
- no animation stutters
- mobile feels designed
- content is easy to understand
- trust is visible
- projects look impressive
- the contact path is effortless
- the website remains fast

# 26. NON-NEGOTIABLE RULES FOR CLAUDE

1. Do not invent company facts.
2. Do not invent projects.
3. Do not invent testimonials.
4. Do not invent certifications.
5. Do not claim unverified project ownership.
6. Inspect existing files before editing.
7. Do not modify unrelated features.
8. Prefer the simplest architecture that achieves the approved experience.
9. Do not add a dependency without a reason.
10. Do not use React state as a per-frame scroll mechanism.
11. Heavy 3D must be lazy-loaded.
12. Every animation must have a purpose.
13. Preserve reduced-motion behavior.
14. Test mobile after major animation changes.
15. Never claim a test passed without running it.
16. Never hide important content behind animation.
17. Do not sacrifice SEO for visual effects.
18. Do not sacrifice performance for visual effects.
19. Do not use a long blocking preloader.
20. Before a major refactor, create a Git checkpoint/commit.
21. Keep business content in a structured data layer where practical.
22. Use real client assets as soon as they are available.
23. Prefer CSS/native browser capabilities when sufficient.
24. Reserve GSAP and Three.js for interactions that genuinely require them.
25. If a proposed animation creates measurable performance problems, redesign the animation instead of merely increasing hardware requirements.
